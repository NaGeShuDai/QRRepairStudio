# 二维码边界升级 1.6

## 实际实现

- `detection.py` 联合 ZXing（包括校验错误候选）与 OpenCV Aruco 多码定位。候选不足时才开启反色、CLAHE、自适应阈值、传统检测及大图原分辨率分块。返回独立目标、来源和备用四角。
- `engine.locate_candidates` 以固定结构评分过滤假候选并选择几何；图像坐标顺序与内容方向独立。界面支持多码选择。
- 全版本轻量定位/定时筛选，十个版本详细评分，前三个版本精修；格式模板缓存容量覆盖全部版本，避免原先 512 项缓存不断淘汰重建。
- `geometry.py` 使用 OpenCV 带模板与输入掩码的 ECC 单应性配准，以定位、定时、校正、版本等已知结构约束透视变换。每次最多两轮，支持固定角点；位移不能超过 1.75 格，覆盖率不能明显下降，原图结构误差必须下降。无法改善时保留原几何。
- 实际采用结构掩码配准，而非重复实现定位图形轮廓提取与 RANSAC。Aruco 提供初始几何，ECC 完成连续精修；大残差显示调整提示。
- 模块中心直接映射回原图，九点探测估计空间稳定性；有效覆盖率与黑白倾向跨度共同降低置信度。没有观测到的区域概率保持 0.5。
- `Sample` 携带自己的几何与质量，旋转/镜像后原图、网格和局部对照保持一致。所有参与最终排名的候选使用相同的采样可靠度模型。
- 纠错失败时，在总时间预算内对确有结构改善的几何最多重试两次。人工编辑与锁定证据保留；新几何随修复候选携带，接受后才应用。
- 选区窗口增加目标选择、固定四角、三点定位和质量提示。三点定位需要版本，用三个中心形成初值，再交给结构精修；不假设三个点能唯一决定一般透视变换。
- 工程设置保存角点锁定；原有工程格式兼容。

## 验证与复现

`tests/test_boundary_pipeline.py` 覆盖不可解码数据损坏、伪内部目标、多目标、空图、取消、缺失像素、精修误差、角点约束、旋转坐标一致性、反馈中的人工证据保存。

`tests/test_ui.py` 增加三点定位与文档状态重置测试。最终完整测试集 83 项通过。

基准包含 32 张确定性合成整图，V1/V3/V7/V12，各种掩码、透视、尺寸、阴影、噪声、模糊。其中 10 张主动破坏数据区、22 张保留原数据。双方从整图自动定位开始，不传入真实四角。对比原始提交的引擎与最终代码。格子错误率相对于实际画出的模块矩阵，包含故意损坏数据的样本；解码指标只统计 22 张完整数据样本。

原始逐例数值、数据集配置、基线提交和汇总在 `boundary-benchmark.json`。基线提取至 `.baseline/engine.py` 后运行：

```powershell
.venv/Scripts/python.exe tools/benchmark_boundary.py --baseline .baseline/engine.py --count 32
```

耗时包含定位、候选筛选、全版本扫描和精修。此测试衡量上述合成条件；不将其当作真实照片总体准确率。另有 V1/V2/V5/V10/V20/V30/V40 自动版本选择检查。

## 当前模型范围

采用平面单应性，弯曲纸面提示结构偏差，不生成无证据的局部形变。QRDet 和超分辨率模型未作为依赖引入：当前基准的区域召回已为 32/32，没有使用模型加载或超分辨率生成像素作为格子证据。后续可依据独立真实失败样本评估增加检测后端。

## 参考接口

- OpenCV QRCodeDetectorAruco 与 Params 官方文档。
- OpenCV findTransformECCWithMask（本机 OpenCV 5.0.0 的双掩码 API）。
- ZXing-C++ Python read_barcodes(return_errors=True)。

运行时保持本地 CPU 推理，不下载模型、不发送图片。

## 最终测量

32 张整图：定位与版本均 32/32，完整数据解码 22/22。平均模块位置误差 0.08518 → 0.05533 格；平均采样位错误率 0.4808% → 0.0507%；定位加网格生成中位耗时 3564 → 498 ms。

源码与独立 EXE 自检均通过（1.6.0），打包源文件哈希逐项匹配。8 张随机噪声/棋盘负样本均未产生二维码候选。现有启动器优先运行 dist-v1.6 中的新版。
